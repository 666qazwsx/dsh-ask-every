# Ask-every clarification protocol

在 base-backed profile 的每个会话中注入一条常驻系统提示词协议（section 名 `ask-every-protocol`，order 10400），并（自 v2.0 起）注册一个引擎级工具 guard 执行门控。自 v2.1 起，协议从"问几个问题"升级为"保证覆盖"的五阶段流程：

**阶段 0：任务分解。** 先把用户消息拆成编号子任务清单（动词开头、可验收），作为第一个弹窗的第一问确认"全对 / 有遗漏 / 有理解偏差"，防止一句话里的多件事被漏做。

**阶段 1：结构化澄清。** 识别任务类型（`code` 代码开发 / `doc` 文档写作 / `research` 调研分析 / `data` 数据表格 / `ops` 运营方案），加载对应模板的必问项（每类 4–6 项）逐项问清；单次弹窗 1–10 问，答完若暴露新决策点，追加最多 `clarifyRounds`（默认 1）轮 2–4 问的追问。模板项为必需覆盖，确实不适用时在问题文本中说明，不得静默跳过。`lite` 模式下退回旧的五维度泛问。

**阶段 2：方案卡。** 2–4 个方向以五字段卡片呈现：目标 / 关键步骤 / 产出物 / 关键假设 / 风险与回退。聊天区展示完整卡片，弹窗选项用"方向名 — 一句话权衡"精简形式。

**阶段 2.5：需求回放。** 执行前列出三类内容：事实（用户明说的，≤8 条）、推断（模型补全的，标注 [推断]，≤5 条）、未确认（开放项及默认处理，≤3 条）。默认并入闸门弹窗（`playback: 'gate'`），也可独立成窗（`'separate'`）或关闭（`'off'`）。用户纠正后回放一次再进闸门。

**阶段 3：执行闸门。** 每次弹窗的最后一问固定为 id `execute_gate` 的闸门问题，选项为「满足，开始执行（推荐）／需要修改（自定义输入说明改哪里）／还有遗漏，我要补充需求」。
- 选「需要修改」→ 修订方案卡后再次弹窗（同样以固定闸门收尾）；
- 选「还有遗漏」→ 回到澄清阶段补问新缺口；
- 修改轮次超过 3 轮后，只聚焦剩余分歧点（至多 3 问），不再整单重列；
- 只有明确选择「满足，开始执行」任务才启动；跳过/超时不作数——协议显式声明优先于宿主工具说明中"跳过的问题不再重问"的字面规则，会简化后重发一次，连续两次跳过视为用户离开，停下等待明确放行。

子代理、团队任务执行者、定时任务消息、goal 自动续跑不受协议约束。闲聊、确认续行、元问题不触发弹窗。用户随时可以说"别问了/你定吧"跳过当前任务（硬门控下会转成一个单问弹窗的点击放行）。

## 引擎级硬门控（v2.0，默认开启，`hardGate: false` 可关）

- 会话默认上锁，每条真实用户消息重新上锁；`ask_user_question` 闸门（id `execute_gate`）点选「满足，开始执行」才开锁。
- 上锁期间 `ctx.tools.guard()` 拒绝白名单外的全部工具调用，拒绝原因引导模型重新弹清单；guard 同步且顺序无关，模型无法通过监听器顺序绕过。
- 白名单默认 `ask_user_question`、`read`、`glob`、`grep`、`web_search`、`web_fetch`、`todo_write`（`preGateTools` 可配，`ask_user_question` 永远保留）。
- 自由输入文字不开锁；需要用户在闸门弹窗上点击。跳过/超时/重启均保持上锁（fail-closed）。
- 子代理会话（origin `subagent`）与无代理调用豁免（`exemptOrigins` 可配）。
- 定时任务、goal 续跑的会话同样会被上锁等待点击；无人值守场景请关闭 `hardGate`。

## 配置（cordis.patch.yml 的 `ask-every` 行）

配置在激活时经 `resolveConfig` 严格校验：未知字段、错误类型直接报错，数值范围自动钳制。

| 字段 | 默认 | 说明 |
|---|---|---|
| `mode` | `standard` | `lite` / `standard` / `deep` 三档预设，显式字段优先于预设 |
| `minQuestions` | `1` | 单次弹窗最少提问数 |
| `maxQuestions` | `10` | 单次弹窗最多提问数（上限 12） |
| `decomposeFirst` | `true` | 首问是否做任务分解确认 |
| `taskTemplates` | 内置五类 | 任务类型模板（label + fields），可整体替换 |
| `clarifyRounds` | `1` | 追问轮数上限（0–3） |
| `playback` | `gate` | 回放位置：`gate` / `separate` / `off` |
| `reaskOnSkip` | `true` | 弹窗被跳过/超时视为未放行，简化后重发一次；`false` 则转为"声明假设后继续" |
| `dimensions` | plan-first 五类 | 补充扫描维度（模板未覆盖时使用），数组，可增删改写成任意语言 |
| `extraRules` | `''` | 追加到协议末尾的自定义规则文本 |
| `gateQuestionId` | `execute_gate` | 闸门问题的固定 id，引擎据此识别放行 |
| `gateQuestion` | 中文默认句 | 闸门问题全文 |
| `gateGoOption` | `满足，开始执行` | 闸门"放行"选项文本 |
| `gateReviseOption` | `需要修改（…）` | 闸门"修改"选项文本 |
| `gateAddOption` | `还有遗漏，…` | 闸门"补充"选项文本 |
| `hardGate` | `true` | 引擎级门控开关；`false` 退回纯提示词模式 |
| `preGateTools` | 只读白名单 | 门控未放行时仍允许的工具名列表 |
| `exemptOrigins` | `['subagent']` | 豁免门控的会话 origin 列表 |
| `gateGoMarkers` | 英文兜底标记 | 额外认可的放行选项关键词 |

## 已知边界

- 门控状态由会话事件流（`session/event` 的真实用户消息、`tools/result` 的闸门放行答案）实时派生，是日志的派生缓存：插件重载或应用重启后 fail-closed 重新上锁，代理会再弹一次闸门。
- 提示词层负责流程编排（问什么、方案怎么列、闸门怎么呈现）；引擎层只负责"没点放行就不放行"。
- 模板覆盖是概率性的：模型识别错任务类型仍可能问偏；需求回放是最后一道兜底，回放清单本身也会限制条数（事实 ≤8、推断 ≤5、未确认 ≤3）。
- 对普通 DSH 会话生效（需安装后重启/新会话）。已存在的旧会话从下一条消息起同样生效。

## 卸载 / 回滚

在 Plugins 面板禁用 `ask-every` 行，或整包移除 `dsh-ask-every`；也可直接删除工作区插件目录 `dsh-ask-every\`。
